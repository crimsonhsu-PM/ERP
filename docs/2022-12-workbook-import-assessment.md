## 2. 重點欄位對照

### 每日營收報表 A6:I6

| 原表欄位 | ERP 欄位／位置 | 處理方式或缺口 |
|---|---|---|
| 日期 | Sale.soldAt | 可保留原始 2022-12 日期，採臺北營業日處理 |
| 購買人 | Sale.customerName | 可保存名字，但不是 Customer 關聯，不能只憑姓名合併客戶 |
| 收入項目 | Item.type | ERP 僅七大類；需建立對照，租賃等無專屬類型，原分類應保留 |
| 收入名稱 | SaleLine.itemId → Item.name | 先建立品項對照；同名、別名、套裝、運費不能只靠文字硬配 |
| 收入形式 | Sale.paymentMethod | 現金／匯款等可對照；恩威帳戶等屬收款帳戶／歸屬，無獨立欄位 |
| 服務者 | Sale.servicePersonId → Employee | 先確認員工別名與角色；不可任意用現有測試人員代替 |
| 記帳者 | 沒有獨立欄；Sale.salesPersonId 是銷售人員 | 兩者角色不同，需確認是否允許視同；原表未提供獨立銷售人員 |
| 金額 | SaleLine.unitPrice×quantity、Sale.total | 原表只有總金額；商品若含多件須還原數量，不能一律數量 1 |
| 備註 | Sale.notes | 資料表可保存；一般營收畫面的匯款資訊也使用 notes，需避免覆蓋原備註 |

一般營收 API 要求銷售人員；除香油捐贈外，每項還需服務人員。原表未給歷史商品成本，現有 SaleLine 也沒有成本快照，不能承諾匯入後自動得到正確歷史毛利。

### 活動名單

- 已支援活動／品項、姓名、登記日期、手機、付款方式、匯款資訊、付款勾選與金額。
- 報名與客戶資料目前沒有生日、地址的專用欄位。原表願望、套餐選項、疏文、領取、入場也沒有對應表單欄位。
- 手機是必填並用來識別客戶。來源六張活動名單沒有手機欄，不能直接用現有流程匯入，也不應捏造手機。
- 現行 API 會以活動品項現價覆蓋報名金額；歷史不同票價需要價格方案或保存實收金額的調整。
- 勾付款會自動產生銷售。必須與每日營收配對後決定建立或連結，否則同一筆錢會記兩次。
- 原表付款勾選與營收紀錄有差異，需要對帳，不能把 FALSE 一概當作確定未付款。

### 點燈與生辰

- ERP 已支援姓名、國曆生日、住址、燈種、年份、點燈日期及價格；API 要求姓名、生日、住址及點燈日期。
- 現有燈種為光明、姻緣、藥師、開悟、招財、女媧。來源還有太歲、寵物光明、平安、天醫、人緣等；天醫是否等於藥師、人緣是否等於姻緣，需要確認，不能自行替換。
- 原始生日混有西元、民國、農曆、時辰及文字。需保留原文和曆別，含農曆者不能僅套字串格式當國曆日期。
- 年度、購買／收款日、真正點燈日與結束日須分開。沒有實際日期時不可補為當日或直接取生日。
- 新增點燈紀錄目前不會自動產生營收，與已付款活動報名的行為不同。

## 3. ERP 尚無完整功能的資訊

1. 人流／付費人次登記及轉換率、ARPU、ARPPU。
2. 客戶儲值、抵扣、餘額與請款追蹤。
3. 每日環境巡檢、逐日勾選、負責人及執行歷史。
4. 場地租借、時段預約、收費及衝突處理。
5. 採購單、供應商、多幣別、匯率、運費及批次成本。
6. 蝦皮刊登／更新及平台資料同步。
7. 設計需求及前置專案的排程、甘特與交付流程。
8. 活動的疏文、願望、報到、元寶／贈品交付等執行流程。
9. 點燈預購／收款／執行、期限、寵物、農曆及時辰資料。
10. 歷史月份及分類目標。現有數據總覽雖能設定營收目標，但存於瀏覽器，月目標沒有年月鍵。
11. Excel 上傳匯入、欄位對照、預覽驗證、批號、防重複及批次回復。現有 Excel 功能是匯出，手動批次新增也不是 Excel 匯入。
12. 現金面額盤點、收款帳戶間存入／轉帳核對、按廠商／商品約定分潤及通知確認。現有零用金有出帳勾選、月報也有服務分潤計算，但不足以完整承接原表個別合約比例、獎金、付款及通知流程。

## 5. 匯入一個月需要多久

以下為本次結構盤點後的工時初估，並非已執行匯入的測速。以一人使用一次性匯入程式、數百筆資料、本機測試環境計算；等待補資料／確認身分不包含在工時內。
