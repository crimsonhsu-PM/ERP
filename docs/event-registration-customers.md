# 活動報名：手機辨識客戶

2026/10/04 更新。適用於 `/events` 的活動報名登記及 `/event-registrations`。

## 表單

- 新增與編輯表單的第一欄為「手機號碼」，顯示必填標記；第二欄為「姓名」，選填。
- 輸入完整且有效的手機後，自動查詢客戶。已存在的號碼帶入先前儲存的姓名，使用者仍可修改或清空。
- 新號碼在儲存報名時一併建立客戶；不必先到另一個頁面建立。
- 開啟舊報名編輯時保留該筆當時的姓名，不因其他報名更新而覆蓋。修改手機時重新查詢。
- 查詢回覆不得覆蓋使用者在等待期間手動輸入的姓名；換號碼後不得帶入前一個號碼的結果。

## 資料規則

- `Customer.id`：內部客戶 ID，維持穩定的報名關聯。
- `Customer.phone`：必填、唯一；台灣手機統一為 `09xxxxxxxx`，接受 `+8869xxxxxxxx`、空白與連字號輸入。海外號碼以 `+國碼` 格式儲存。
- `Customer.name`：可空；儲存報名時明確提交的姓名會成為下次查詢的預設值。
- `EventRegistration.customerId`：必填，外鍵連到 `Customer.id`；同一位客戶可以有多筆報名。
- `EventRegistration.phone`：必填，記錄本次報名手機。
- `EventRegistration.attendeeName`：可空，保留本次報名的姓名。未提交姓名時帶入客戶現有姓名，明確送出空字串表示留白。
- 共用手機視為同一位客戶；不按姓名合併客戶。
- 刪除報名不刪客戶；有報名關聯的客戶不可直接刪除。
- 只切換付款狀態時不更新客戶姓名；既有報名的姓名與已產生營收保留原有流程。

## API

- `GET /api/event-registrations/customer-lookup?phone=...`：需活動管理權限，精確查詢正規化手機，回傳 `{ found, name }`，不回傳完整客戶資料；無登入 401、無權限 403、格式錯誤 400。
- `POST /api/event-registrations`：手機必填，依手機取得或建立客戶並寫入 `customerId`；客戶、報名及付款產生的營收在同一交易內處理。
- `PATCH /api/event-registrations/:id`：未提交手機保留原值；明確空白或無效手機回傳 400。換號碼會連到新號碼對應的客戶，不修改其他報名。
- 客戶關聯由伺服器依手機決定；提交不符的 `customerId` 或直接嵌入 `customer` 關聯回傳 400。
- `/api/customers` 的新增與修改也正規化手機；重複號碼回傳 409。

## 舊資料處理與驗證

已先備份資料庫，按使用者授權刪除 `Crimsontest01` 測試報名及其產生的營收。其餘 24 筆報名全部連結客戶，現有 22 位客戶；保留報名原有姓名、日期、付款與金額。

`scripts/backfill-registration-customers.ts` 預設僅預覽，`--apply` 才寫入。遇到缺少手機、重複客戶手機或既有關聯與手機不符時停止，不猜測關聯。應先備份、處理異常、補關聯，再執行 Prisma schema 同步。

`scripts/registration-customer-test.ts` 使用独立暫存資料庫，驗證手機正規化、唯一性、姓名選填、權限、編輯、付款、交易回滾及刪除保留客戶。
